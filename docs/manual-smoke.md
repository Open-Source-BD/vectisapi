# Manual smoke checklist

GUI-only checks that no automated test covers (the Rust core, the UI with a mocked Rust layer and
the CSP are covered by `cargo test`, Vitest and Playwright). Run on a release build
(`npm run tauri build`, then open `target/release/bundle/macos/VectisAPI.app`, the `.msi`/`.exe`,
or the AppImage/`.deb`) unless a step says `tauri dev`.

Record date, OS, build and pass/fail per item.

Data folder (for "delete the database" steps): macOS `~/Library/Application Support/dev.vectisapi.app/`,
Windows `%APPDATA%\dev.vectisapi.app\`, Linux `~/.local/share/dev.vectisapi.app/`.

## 1. Persistence on close

**1a. Window close flushes edits**
1. Launch. In the active tab type the URL `https://example.test/flush-close-1`.
2. Within 1 second of the last keystroke, close the window (red button / Alt+F4 / window ✕).
3. Relaunch.

Expected: the tab shows `https://example.test/flush-close-1`. The app quits within ~1 s of closing.

**1b. Quit shortcut (Cmd+Q on macOS; Ctrl+Q / app menu Quit elsewhere)**
1. Rename a collection to `flush-quit-1` (Collections → right-click → Rename → Enter).
2. Within 1 second press Cmd+Q.
3. Relaunch.

Expected: the collection is named `flush-quit-1`; the app quit promptly (no hang, no dialog).

**1c. Environment edit + quit from the Dock / taskbar menu**
1. Environments → add variable `smoke` = `1` → close the modal → immediately Quit from the Dock /
   taskbar context menu.
2. Relaunch, open Environments.

Expected: `smoke` = `1` is there.

## 2. Startup error dialog with a newer-schema database

1. Quit the app. Back up `vectisapi.db` (copy it elsewhere).
2. Run `sqlite3 vectisapi.db "PRAGMA user_version = 999;"` in the data folder.
3. Launch.

Expected: no main window; a native error dialog "VectisAPI could not open its database and will
quit." mentioning "database schema version 999 is newer than this app supports". Clicking OK quits
(exit code 1). The database file is unchanged.

4. Restore the backup copy and launch: the workspace is back.

## 3. Native dialogs

**3a. Backup export/import**
1. Settings → **Export all** → a native Save dialog opens; save `smoke-backup.json` to the Desktop.
2. Delete a collection. Settings → **Import all** → pick `smoke-backup.json`.

Expected: the dialog titles/filters look native; the deleted collection is back after import; the
file is valid JSON.

**3b. Response download**
1. Send `GET https://httpbin.org/image/png` (or any local PNG URL).
2. Response → **Download** → save.

Expected: native Save dialog with a sensible file name; the saved file opens as the same image and
its byte size equals the response Size.

**3c. Form-data file pick**
1. New tab, `POST https://httpbin.org/post`, Body → formdata, row key `file`, type **File** →
   click **Choose file** → pick a small text file.
2. Send.

Expected: native Open dialog; the cell then shows the file name (full path on hover); the response
`files.file` contains the file's text.

**3d. next-postman import**
1. Settings → **Import next-postman workspace (zip)** → pick a zipped next-postman workspace folder.
2. Repeat with **(folder)** on the unzipped folder.

Expected: native Open dialog filtered to `.zip` (zip) / a folder picker (folder); collections,
nested folders/requests and environments appear; importing twice does not duplicate (merge by id).

**3e. Open data folder**: Settings → **Open data folder** opens Finder / Explorer / the file
manager at the folder containing `vectisapi.db`.

## 4. Realtime against real servers

**4a. WebSocket**
1. New tab → protocol **WS**, URL `wss://echo.websocket.org` (or a local echo server, e.g.
   `npx wscat --listen 8080` → `ws://localhost:8080`).
2. Headers tab: add `X-Smoke: 1` (and with a local server, confirm it arrives in the handshake).
3. Connect; send `hello` and `{"a":1}`; Disconnect.

Expected: status Connecting → Connected; sent rows (↗) followed by echoed rows (↙) in order, with
byte counts and times; Disconnect shows `code 1000`/`1005`. The custom header is sent (local server).

**4b. SSE**
1. Protocol **SSE**, URL of a live stream (e.g. a local `npx sse-fake-server` or any
   `text/event-stream` endpoint). Connect.

Expected: events stream in as rows (named events prefixed `[event]`); Disconnect stops it; a server
close shows "Stream ended".

**4c. Log cap**: against a fast WS source, leave it running past 5,000 messages. Expected: the
"… N older messages trimmed" notice appears at the top, memory stays flat, scrolling stays smooth.

## 5. Large body

1. Serve a 50 MB JSON file locally (e.g. `python3 -m http.server` in a folder with `big.json`
   generated by `python3 -c "import json;print(json.dumps([{'id':i,'name':'row'} for i in range(900000)]))" > big.json`).
2. `GET http://localhost:8000/big.json` → Send.

Expected: the first rows appear well under a second with "Preview only — showing the start of a
50 MB body"; the UI stays responsive (switching tabs, typing in the URL bar) while the response
arrives. Scroll top-to-bottom quickly: no blank flashes longer than a frame, no stutter.
3. **Load full body**: a short hitch (≲0.5 s) is acceptable; afterwards scrolling to the very end is
   smooth and the last line is the end of the JSON. Download writes the exact 50 MB.

## 6. Scripts in the real webview (CSP)

1. Scripts tab: `pm.environment.set("seg", "ok");` URL `https://httpbin.org/anything/{{seg}}` → Send.
2. Tests tab: `pm.test("status", () => pm.expect(pm.response.code).to.eql(200));` → Send.
3. Scripts tab: `while (true) {}` → Send.

Expected: (1) the request goes to `/anything/ok`; (2) the test passes; (3) after ~5 s a script
timeout error, the UI never freezes. Never "Scripts are blocked by the content security policy"
(this is the WKWebView / WebView2 / WebKitGTK confirmation of `e2e/csp.spec.ts`).

## 7. Other platforms (if available)

On Windows 10/11 and a Linux desktop (X11 and Wayland):
1. `npm ci && npm run tauri dev` starts the app; repeat sections 1, 3c, 4a and 6.
2. Install the release `.msi`/NSIS and AppImage/`.deb`; launch from the Start menu / app launcher.
3. Linux: if the window is blank, relaunch with `WEBKIT_DISABLE_DMABUF_RENDERER=1` (README) and
   note the GPU/driver.

Expected: same behaviour as macOS; the window icon is the blue "V" tile; fonts and icons render
(no ligature text like `send` instead of icons).

## 8. Startup and idle

1. Launch from Finder / Start menu with the app not cached (after a reboot if possible).

Expected: the window appears with the UI interactive in under 1 s; Activity Monitor / Task Manager
shows total memory for the app's processes (app + WebContent/WebView2 helpers) under ~150 MB at
idle.

## 9. Modal backdrop blur in the real webview

1. Open any modal (Environments, Cookies via Cmd/Ctrl+K → "Manage cookies", Settings).

Expected: the app behind the modal is dimmed **and slightly blurred**, as in
`docs/fidelity/4-env-modal-light-np.png` (NP, Chromium). Headless Playwright WebKit showed a flat
grey scrim without blur (`*-va-webkit.png`); record whether WKWebView (macOS), WebView2 (Windows)
and WebKitGTK (Linux) blur. If one doesn't, note the OS/webview version: the CSS uses unprefixed
`backdrop-filter`, which older WebKit only supports as `-webkit-backdrop-filter`.
